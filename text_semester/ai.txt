Chapter 1: Introduction to AI

1.1 Defining Artificial Intelligence

AI is the study of systems that receive percepts from the environment and perform actions.
Historically, AI has been defined along two dimensions:
  Dimension 1: Thought processes/reasoning vs. Behavior/action
  Dimension 2: Human-like (Empirical) vs. Rational (Ideal/Mathematical) performance

  The Four Definitions of AI:

  +----------------+----------------------------------------------+--------------------------------------------------+
  |                | Human-Like (Empirical)                       | Rational (Ideal / Mathematical)                  |
  +----------------+----------------------------------------------+--------------------------------------------------+
  | THINKING       | Thinking Humanly (Cognitive Science):         | Thinking Rationally (Laws of Thought):           |
  |                | Matching machine reasoning step-by-step       | Using formal logic (e.g. Aristotle's syllogisms) |
  |                | with human cognitive processes.               | to make correct inferences. Focuses on           |
  |                | Method: cognitive modeling, brain imaging.    | codifying "right thinking" using logic systems.  |
  +----------------+----------------------------------------------+--------------------------------------------------+
  | ACTING         | Acting Humanly (Turing Test):                 | Acting Rationally (Rational Agents):             |
  |                | Systems that perform actions requiring        | Agents that act to achieve the best outcome      |
  |                | intelligence if done by humans. Evaluated     | or best expected outcome under uncertainty.      |
  |                | by indistinguishability from humans.          | Focuses on goal-directed behavior.               |
  +----------------+----------------------------------------------+--------------------------------------------------+


1.2 The Turing Test (Alan Turing, 1950)

Alan Turing proposed the "Imitation Game" to replace the philosophical question
"Can machines think?" with a behavioral test of intelligence.

  +------------------------+
  |  Human Evaluator (C)   |
  +------------------------+
        | (Text Queries Only)
   +----+----+
   v         v
+----------+  +----------+
|Computer  |  | Human(B) |
|   (A)    |  |          |
+----------+  +----------+

Test Setup & Mechanics:
- Participants: A computer (A), a human (B), and a human evaluator (C).
- Protocol: Evaluator communicates with both via written text ONLY (separated from A and B).
- Goal: C must determine which terminal is the computer and which is the human.
- Success Condition: If evaluator cannot distinguish computer from human after 5 minutes, computer PASSES.

Core Capabilities Required to Pass the Turing Test:
1. Natural Language Processing (NLP): To communicate successfully in a natural language (English, Hindi, etc.).
2. Knowledge Representation: To store facts, experiences, and information received during conversation.
3. Automated Reasoning: To use stored information to answer questions, draw conclusions, and detect contradictions.
4. Machine Learning: To adapt to new circumstances, learn from past mistakes, and detect patterns.

The Total Turing Test (Extended Version):
The computer must also interact physically with the environment. This additionally requires:
- Computer Vision: To perceive objects, recognize faces, and navigate.
- Robotics: To manipulate objects, move around, and perform physical actions.


1.3 History of Artificial Intelligence

The evolution of AI is marked by waves of intense optimism followed by disappointment and funding cuts (AI Winters).

Key Milestones:
  1943 : McCulloch-Pitts Neuron — First mathematical model of an artificial neuron.
  1950 : Turing Test Proposed — Alan Turing's "Computing Machinery and Intelligence" paper.
  1956 : Dartmouth Workshop — John McCarthy coins "Artificial Intelligence". Birth of the field.
  1956-1974 : The Golden Years — Search algorithms, ELIZA chatbot, block world planning.
  1974-1980 : FIRST AI WINTER — Lighthill Report; combinatorial explosion; funding dry-up.
  1980-1987 : Expert Systems Boom — Commercial success of MYCIN (medical diagnosis) and XCON/R1.
  1987-1993 : SECOND AI WINTER — Collapse of specialized LISP machine market; high maintenance costs.
  1993-Now  : Modern Era — Deep Blue (1997), IBM Watson (2011), AlexNet (2012), AlphaGo (2016), GPT/LLMs.

The Two AI Winters Explained:
- First AI Winter (1974-1980):
  Caused by: Combinatorial explosion in search spaces + severe limitations of early models.
  Minsky and Papert proved that Perceptrons CANNOT learn the XOR function.
  Result: Government funding (DARPA, UK Council) was drastically slashed.

- Second AI Winter (1987-1993):
  Caused by: High cost and maintenance difficulty of Expert Systems.
  Expert systems were fragile, hard to update, could not handle uncertainty.
  Collapse of specialized LISP machine hardware market in favor of standard desktop PCs.


Chapter 2: Problem Solving Methods

2.1 State Space Search Formulation

In AI, problem-solving is framed as goal-directed search through a state space.
A search problem is formally defined by FIVE components:

1. Initial State: The state where the agent starts. Example: In(Arad).
2. Actions: Set of actions available to the agent in state s. Actions(s) returns the list of applicable actions.
3. Transition Model: Result(s, a) returns the state reached by executing action a in state s.
4. Goal Test: A function that determines whether a given state is a goal state. Example: s = In(Bucharest).
5. Path Cost: A function assigning a numeric cost to a path (e.g., sum of distances between cities).


2.2 Uninformed Search Strategies (Blind Search)

Uninformed search has NO domain-specific knowledge about distance from current state to goal.
Can only generate successors and test whether a state is a goal.

  Performance Comparison Matrix — Uninformed Search Strategies:

  +------------------------+-----------------+-----------------+------------------+------------------+-----------+
  | Search Strategy        | Frontier Type   | Complete?       | Time Complexity  | Space Complexity | Optimal?  |
  +------------------------+-----------------+-----------------+------------------+------------------+-----------+
  | BFS (Breadth-First)    | FIFO Queue      | YES (if b<inf)  | O(b^d)           | O(b^d) [Heavy!]  | YES (uniform cost) |
  | DFS (Depth-First)      | LIFO Stack      | NO (infinite)   | O(b^m)           | O(b*m) [Linear!] | NO        |
  | DLS (Depth-Limited)    | LIFO + limit l  | NO (if d > l)   | O(b^l)           | O(b*l)           | NO        |
  | IDS (Iterative-Deep)   | LIFO (incr l)   | YES (if b<inf)  | O(b^d)           | O(b*d) [Linear!] | YES (uniform cost) |
  | UCS (Uniform Cost)     | Priority Queue  | YES (cost>eps)  | O(b^(1+C*/eps))  | O(b^(1+C*/eps))  | YES (any positive cost) |
  +------------------------+-----------------+-----------------+------------------+------------------+-----------+

  Key Notation:
  - b = branching factor (average number of successors per node)
  - d = depth of the shallowest goal node
  - m = maximum depth of the state space (may be infinite)
  - C* = cost of the optimal solution
  - eps = minimum step cost (epsilon, must be > 0)

  IDS (Iterative Deepening Search) is the PREFERRED uninformed strategy:
  - Same time complexity as BFS: O(b^d)
  - Same EXCELLENT space complexity as DFS: O(b*d)
  - Complete AND Optimal (for uniform step costs)


2.3 Informed (Heuristic) Search Strategies

Informed search uses domain-specific knowledge via a heuristic function h(n) to guide the search.
- h(n) = estimated cost of the cheapest path from node n to a goal node.
- h(Goal) = 0 always.

--- Greedy Best-First Search ---
  Evaluation Function: f(n) = h(n)
  Strategy: Always expands the node that APPEARS closest to the goal.
  Completeness: NO (can get stuck in loops).
  Optimality: NO (may find a suboptimal path).

--- A* Search ---
  Evaluation Function: f(n) = g(n) + h(n)
  - g(n) = actual path cost incurred from start to node n.
  - h(n) = estimated cost from n to the goal (heuristic).
  - f(n) = estimated TOTAL cost of path through n to the goal.

  Conditions for A* Optimality:
  1. Admissibility (for Tree Search): h(n) must NEVER overestimate the actual cost.
     Formally: h(n) <= h*(n), where h*(n) is the true optimal cost to goal.

  2. Consistency / Monotonicity (for Graph Search):
     For every node n and successor n' via action a:
     h(n) <= c(n, a, n') + h(n')
     (Triangle inequality must hold)

  Note: A consistent heuristic is ALWAYS admissible. When these conditions hold,
  A* is GUARANTEED to find the optimal path.

--- AO* Search (AND-OR Graphs) ---
  Used for decomposing a main problem into smaller sub-problems.
  - OR Nodes: Represent CHOICE points. Solve either Subproblem A OR Subproblem B.
  - AND Nodes: Represent DECOMPOSITION points. Must solve Subproblem A AND Subproblem B.
  - Evaluation: Updates heuristics backwards from leaf nodes using path cost formulas for AND/OR splits.


2.4 Local Search & Optimization

Local search algorithms operate using a SINGLE CURRENT NODE (not maintaining a full search tree).
They are HIGHLY SPACE-EFFICIENT.

--- Hill Climbing Search ---
  A simple loop that continuously moves in the direction of INCREASING VALUE (Steepest Ascent).

  Value/Objective Function
       ^
       |        Local Maximum
       |           .---.
       |          /     \
       |         /       \       Global Maximum
       | Plateau/         \          .---.
       | --------          \        /     \
       |                    \      /       \
       |                     \____/         \
       +---------------------------------------------> State Space

  Three Main Pitfalls of Hill Climbing:
  1. Local Maxima: A peak higher than all neighboring states but lower than the global maximum.
     Algorithm GETS STUCK because all moves lead downward.

  2. Ridges: A sequence of local maxima joined together. The slope is steep on both sides
     but very gentle along the ridge itself. Causes search to oscillate and stall.

  3. Plateaus: A flat area where the evaluation function is uniform.
     Algorithm conducts a random walk without clear direction ("shoulder" or flat local maximum).

--- Simulated Annealing ---
  Designed to ESCAPE local maxima by combining hill climbing with random walks.

  Rules:
  - If a neighboring state has a BETTER value: Accept it IMMEDIATELY.
  - If the neighbor has a WORSE value: Accept it with probability P = e^(delta_E / T)
    where delta_E = difference in objective values (negative for worse moves),
    and T = "Temperature" parameter that starts HIGH and DECREASES via annealing schedule.

  Intuition:
  - Early (high T): Agent accepts bad moves easily to EXPLORE the state space.
  - As T approaches 0: Agent becomes strictly greedy, settling into the global optimum.
  - If T decreases slowly enough: Will find global optimum with probability 1.


2.5 Constraint Satisfaction Problems (CSP)

A CSP defines a state space where states are ASSIGNMENTS of values to variables.

Components:
- Variables (X): A set of variables {X1, X2, ..., Xn}.
- Domains (D): A set of allowable values for each variable {D1, D2, ..., Dn}.
- Constraints (C): Rules specifying allowed combinations. Example: X1 != X2.

A state is COMPLETE and CONSISTENT if all variables are assigned and no constraint is violated.

--- Constraint Propagation (AC-3 Algorithm) ---
  Instead of blind search, we PRUNE variable domains before or during search.

  Arc Consistency: A directed arc Xi --> Xj is consistent if:
  For every value x in Di, there EXISTS some value y in Dj that satisfies the Xi-Xj constraints.

  AC-3 Algorithm:
  1. Maintain a queue of all arcs.
  2. For each arc Xi --> Xj: if it is INCONSISTENT, remove values from Di to make it consistent.
  3. Re-add all neighboring arcs Xk --> Xi to the queue to PROPAGATE changes.
  4. Repeat until queue is empty.

  Advantage: Dramatically prunes search space before starting backtracking search.

--- Cryptarithmetic Example ---
       S E N D
     + M O R E
     ---------
     M O N E Y

  Variables: {S, E, N, D, M, O, R, Y} from {0, 1, ..., 9}
  Carries: {C1, C2, C3, C4} from {0, 1}
  Constraints:
    - All different: Alldiff(S, E, N, D, M, O, R, Y)
    - S != 0, M != 0
    - D + E = Y + 10*C1
    - N + R + C1 = E + 10*C2
    - E + O + C2 = N + 10*C3
    - S + M + C3 = O + 10*C4
    - C4 = M --> Since M != 0 and C4 is 0 or 1, we INFER M = 1 instantly by constraint propagation!


2.6 Adversarial Search (Game Playing)

Adversarial search involves environments where multiple agents COMPETE.
Examples: Chess, Tic-Tac-Toe, Checkers.

--- Minimax Algorithm ---
  Used in two-player, ZERO-SUM, PERFECT-INFORMATION games.
  - MAX Player: Seeks to MAXIMIZE game utility.
  - MIN Player: Seeks to MINIMIZE game utility.

  Minimax(s) =
    Utility(s)                           if Terminal(s)
    max over a of Minimax(Result(s,a))   if Player(s) = MAX
    min over a of Minimax(Result(s,a))   if Player(s) = MIN

  Time Complexity: O(b^m) where b = branching factor, m = maximum tree depth.
  Space Complexity: O(b*m) using depth-first exploration.

--- Alpha-Beta Pruning ---
  Optimization that returns the EXACT SAME MOVE as Minimax but PRUNES branches
  that cannot affect the final decision. Dramatically reduces computation.

  Diagram:
             MAX [alpha=3]
               /          \
              /            \
        MIN [3]          MIN [beta=2]  <-- PRUNED! (alpha >= beta, i.e., 3 >= 2)
         /    \              /     \
        3      12           2    [Not Evaluated]

  Alpha (alpha): The BEST (highest) choice found along the path for MAX so far.
  Beta (beta): The BEST (lowest) choice found along the path for MIN so far.
  Pruning Rule: If at any node, alpha >= beta, PRUNE the remaining branches.

  Best Case Performance (optimal ordering): O(b^(m/2)) -- doubles searchable depth!
  Average Case: O(b^(3m/4))

--- Stochastic Games (Expectiminimax) ---
  For games with CHANCE/PROBABILISTIC elements (e.g., dice in Backgammon).
  - Chance Nodes: Added BETWEEN MAX and MIN layers.
  - Value of a chance node = EXPECTED VALUE of its children:
    Expectiminimax(s) = sum over r of [P(r) * Expectiminimax(Result(s,r))]
    where P(r) is the probability of outcome r.


Chapter 3: Knowledge Representation

3.1 Knowledge Representation Schemes

Knowledge must be represented internally in formats that allow computers to draw inferences.

--- Semantic Networks ---
  Represent knowledge as a DIRECTED GRAPH.
  - Nodes: Represent objects, concepts, or situations.
  - Edges: Represent relationships between nodes.
  Common relations:
    - is-a: Class inheritance. Example: Dog --is-a--> Mammal
    - has-a: Part-whole relation. Example: Car --has-a--> Engine

--- Frame Representation ---
  A RECORD-LIKE data structure containing collection of attributes (SLOTS) and their values (FILLERS).
  Supports default values and inheritance.

  Example Frame:
    Frame: Dog
      Inherits: Mammal
      Slots:
        Legs: 4 (Default value)
        Barks: True
        Owner: Unknown (unfilled slot)

  Advantages:
  - Easy to represent real-world objects with complex attributes.
  - Supports inheritance (Dog inherits properties of Mammal automatically).

--- Conceptual Dependency (Schank's Theory) ---
  A theory for representing the SEMANTICS of natural language sentences by breaking them into
  fundamental psychological PRIMITIVE ACTS:

  - ATRANS: Transfer of an abstract relationship. Examples: giving, buying, selling.
  - PTRANS: Transfer of physical location of an object. Examples: walking, throwing, driving.
  - MTRANS: Transfer of mental information between minds. Examples: telling, remembering, reading.
  - PROPEL: Application of physical force to an object. Examples: pushing, pulling, kicking.


3.2 First-Order Predicate Logic (FOPL)

While Propositional Logic deals only with true/false facts, FOPL represents objects, properties,
and relations using quantifiers.

Key Symbols:
- Universal Quantifier (for all): "For all". Typically used with IMPLICATION (-->).
  Example: "All students are smart" --> for all x (Student(x) --> Smart(x))

- Existential Quantifier (there exists): "There exists at least one". Used with CONJUNCTION (AND).
  Example: "Some students are smart" --> there exists x (Student(x) AND Smart(x))

  COMMON FALLACY WARNING:
  Writing "All students are smart" with AND:
  for all x (Student(x) AND Smart(x))
  This wrongly means "Everyone in the universe is a student AND everyone is smart."
  CORRECT: Use IMPLICATION (-->) with Universal Quantifier, not AND!


3.3 Logical Inference & Reasoning

--- Inference Rules ---
  Modus Ponens:
    Given: P --> Q  (if P then Q)
    Given: P        (P is true)
    Conclude: Q     (therefore Q is true)

  Modus Tollens:
    Given: P --> Q  (if P then Q)
    Given: NOT Q    (Q is false)
    Conclude: NOT P (therefore P is false)

--- Unification ---
  The algorithmic process of finding a substitution theta of variables that makes two predicate
  expressions IDENTICAL.

  Example:
    Expression 1: Knows(John, x)
    Expression 2: Knows(John, Jane)
    Unification result: theta = {x/Jane}  (substitute Jane for x to make them identical)

--- Resolution Refutation (Proof by Contradiction) ---
  To prove statement alpha from Knowledge Base (KB):
  1. Add NOT alpha to KB.
  2. Convert ALL statements in KB to Conjunctive Normal Form (CNF).
  3. Repeatedly apply the RESOLUTION RULE on pairs of clauses to derive new clauses.
  4. If we derive the EMPTY CLAUSE (contradiction), then alpha is PROVED.

  CNF Conversion Algorithm (7 Steps):
  Step 1: Eliminate Implications: Replace P --> Q with (NOT P OR Q).
  Step 2: Move Negation Inward: Apply De Morgan's laws.
            NOT(P AND Q) becomes (NOT P OR NOT Q)
            NOT(for all x P) becomes (there exists x NOT P)
  Step 3: Standardize Variables: Rename so each quantifier binds a UNIQUE variable name.
  Step 4: Skolemize Existential Quantifiers:
    - If existential, replace with Skolem CONSTANT: there exists x Crown(x) --> Crown(C1)
    - If depends on other variables, use Skolem FUNCTION:
      for all x there exists y Person(x) --> Loves(x,y)
      becomes: for all x Person(x) --> Loves(x, f(x))  [Skolem function f(x)]
  Step 5: Drop Universal Quantifiers (all remaining variables are implicitly universal).
  Step 6: Distribute OR over AND to achieve CNF form.

--- Chaining Algorithms ---

  FORWARD CHAINING (Data-Driven):
  [Known Facts] --> [Apply Rules] --> [Infer New Facts] --> ... --> [Goal]
  - Starts with KNOWN FACTS in the database.
  - Applies rules to INFER new facts.
  - Repeats until goal is reached or no new facts can be inferred.
  - Used in: Production systems, business rule engines.

  BACKWARD CHAINING (Goal-Driven):
  [Goal] <-- [Find Rules that Conclude Goal] <-- [Verify Rule Premises] <-- [Facts]
  - Starts with the GOAL.
  - Checks if goal is already known. If not, finds rules whose CONCLUSION is the goal.
  - Recursively tries to PROVE the premises of those rules.
  - Used in: PROLOG, medical diagnostic systems.


3.4 Ontological Engineering

Ontological engineering is the process of defining the BASIC CATEGORIES, objects, situations,
and events in a domain to create a shared, structured vocabulary.

- Categories vs. Instances:
  Organizing concepts hierarchically.
  Example: Vegetable (category) --> Carrot (subcategory) --> specific carrot on a plate (instance).

- Non-monotonic Reasoning:
  Standard logic is MONOTONIC: adding new facts only INCREASES the set of truths.
  AI uses NON-MONOTONIC reasoning: default assumptions can be RETRACTED when contradicting
  evidence arrives.
  Example: Assume a bird CAN FLY by default.
           Learn it is a PENGUIN. Retract the flying assumption.


Chapter 4: Software Agents

4.1 Basic Definitions

Agent: Anything that can PERCEIVE its environment through SENSORS and ACT on that
environment through ACTUATORS.

- Sensor: Device or mechanism that inputs PERCEPTS. Examples: cameras, sonar, microphone, keyboard.
- Actuator: Device or mechanism that outputs ACTIONS. Examples: robotic arms, display, motors.
- Percept Sequence: Complete history of EVERYTHING the agent has ever perceived.
- Agent Function: Maps from any percept sequence to an action: f: Percept* --> Action.

When designing an agent, define the task environment using PEAS:
P = Performance Measure, E = Environment, A = Actuators, S = Sensors

4.3 Environment Properties

1. Observable: Fully vs. Partially Observable
   - Fully Observable: Sensors detect the COMPLETE state of the environment at any time.
   - Partially Observable: Missing data due to noise, limited sensor range, or incomplete information.

2. Deterministic vs. Stochastic/Nondeterministic:
   - Deterministic: Next state is COMPLETELY determined by current state and agent's action.
   - Stochastic: Involves chance/probability (outcomes not fully determined by action).

3. Episodic vs. Sequential:
   - Episodic: Experience divided into INDEPENDENT episodes. Current action does NOT affect future.
     Example: Classifying images (each image is independent).
   - Sequential: CURRENT decisions affect FUTURE states. Must plan ahead.
     Example: Chess (each move affects future game states).

4. Static vs. Dynamic:
   - Dynamic: Environment CHANGES while agent is deliberating. Example: Taxi driving.
   - Static: Environment does NOT change while agent decides. Example: Crossword puzzle.

5. Discrete vs. Continuous:
   - Discrete: FINITE, distinct set of states and actions. Example: Chess, Tic-Tac-Toe.
   - Continuous: INFINITE, continuous state/action ranges. Example: Driving a car.

6. Single-agent vs. Multi-agent:
   - Single-agent: Agent operates ALONE. Example: Solitaire, crossword puzzle.
   - Multi-agent: Other agents whose actions affect performance. Example: Chess, auction bidding.

  Hardest environment to operate in: Partially observable + Stochastic + Sequential + Dynamic + Continuous + Multi-agent.


4.4 Agent Architectures

--- Simple Reflex Agent ---
  Selects actions based ONLY on the CURRENT PERCEPT. Ignores percept history.
  Uses condition-action rules (IF-THEN rules).

  Example rule: IF car_in_front_is_braking THEN initiate_braking

  Flow: Percept --> [Condition-Action Rules] --> Action

  Limitation: Does NOT work in partially observable environments (cannot remember past).

--- Model-Based Reflex Agent ---
  Maintains an INTERNAL STATE to track aspects of the environment NOT currently visible.
  Uses a model of how the world works to update the internal state.

  Flow: Percept --> [Update Internal State using World Model] --> [Condition-Action Rules] --> Action

  Advantage: Can handle PARTIAL OBSERVABILITY using stored memory of past percepts.

--- Goal-Based Agent ---
  Uses GOAL INFORMATION to select actions that will lead to a desired goal state.
  Combines state tracking with planning.

  Flow: Percept --> [Update State] --> [What will happen if I do action X?] --> [Goal Check] --> Action

  Advantage: More flexible than reflex agents. Can achieve goals through different action sequences.

--- Utility-Based Agent ---
  Uses a UTILITY FUNCTION to map states to real numbers, measuring how DESIRABLE a state is.
  Allows making trade-offs when multiple goals conflict.

  Flow: Percept --> [Update State] --> [Evaluate Utility of Possible States] --> Action

  Advantage: Can compare competing goals and choose the BEST EXPECTED outcome under uncertainty.

--- Learning Agent ---
  Divided into FOUR conceptual components:
  - Learning Element: Makes improvements based on FEEDBACK from the Critic.
  - Performance Element: Selects EXTERNAL ACTIONS (the operational part of the agent).
  - Critic: Evaluates agent's behavior against an EXTERNAL PERFORMANCE STANDARD.
  - Problem Generator: Suggests NEW EXPLORATORY actions (experiments) to discover better strategies.

  Flow: Critic evaluates --> Learning Element improves --> Performance Element acts --> Critic evaluates again.

  Architecture Comparison:
  +----------------------+------------------+-------------------+-----------------+------------------+
  | Architecture         | Uses Memory?     | Uses Goals?       | Uses Utility?   | Can Learn?       |
  +----------------------+------------------+-------------------+-----------------+------------------+
  | Simple Reflex        | NO               | NO                | NO              | NO               |
  | Model-Based Reflex   | YES (world model)| NO                | NO              | NO               |
  | Goal-Based           | YES              | YES               | NO              | NO               |
  | Utility-Based        | YES              | YES               | YES             | NO               |
  | Learning Agent       | YES              | YES               | YES             | YES              |
  +----------------------+------------------+-------------------+-----------------+------------------+


Chapter 5: Applications of AI

5.1 Natural Language Processing (NLP)

NLP enables machines to READ, UNDERSTAND, and DERIVE MEANING from human languages.

- Syntactic Analysis (Parsing): Analyzing grammar rules and sentence structure.
  Example: Parse tree showing noun phrase, verb phrase decomposition.

- Semantic Analysis: Extracting MEANING and resolving ambiguity.
  - Word Sense Disambiguation: Determining correct meaning of a word in context.
  - Example: "Bank" means financial institution OR riverbank depending on context.

- Information Retrieval (IR): Finding documents RELEVANT to user queries.
  - TF-IDF (Term Frequency-Inverse Document Frequency): Weights term importance.
  - PageRank: Ranks web pages by link importance (used in Google Search).

- Information Extraction (IE): Acquiring STRUCTURED DATA from unstructured text.
  - Named Entity Recognition (NER): Extracting people, places, organizations from text.

- Machine Translation: Converting text from one language to another.
  - Modern approaches: Neural Machine Translation (Transformer-based models).

- Speech Recognition: Converting spoken language to written text.
  - Applications: Siri, Google Assistant, Amazon Alexa.


5.2 Robotics

Robotics deals with PHYSICAL AGENTS that perform tasks by manipulating physical environments.

- Sensors: Convert physical properties (light, sound, distance) to digital signals.
  Types: LIDAR (Light Detection and Ranging), sonar, tactile sensors, cameras.

- Actuators: Execute physical actions.
  Types: Electric motors, hydraulic pistons, pneumatic systems (move joints and wheels).

- SLAM (Simultaneous Localization and Mapping):
  Helps robots BUILD A MAP of an unknown environment while simultaneously TRACKING their
  own location within it. Essential for autonomous navigation.

- Path Planning: Calculating OPTIMAL TRAJECTORIES through configuration spaces.
  Algorithms used: A* search, potential fields, probabilistic roadmaps (PRM).


5.3 Expert Systems

An expert system is an interactive computer system that MIMICS the decision-making ability
of a human expert in a specific domain.

  Architecture of an Expert System:

  +------------------+
  |  User Interface  |  <-- User enters symptoms/queries, receives recommendations
  +--------+---------+
           | Queries / Answers
  +--------v---------+
  | Inference Engine |  <-- Applies rules and logical reasoning
  +--------+---------+
           | Matches Rules to Facts

  +------------------+

  Components:
  - Knowledge Base: Stores domain-specific facts and heuristic rules (IF-THEN rules).
    Example: IF patient has fever AND cough THEN suspect pneumonia.
  - Inference Engine: Applies logical rules to the knowledge base to deduce new information
    or answer user queries. Uses Forward or Backward chaining.
  - User Interface: Provides interactive portal for non-expert users to enter data
    and receive explanations/recommendations.

  Famous Expert Systems:
  - MYCIN: Medical diagnosis of bacterial infections (Stanford, 1970s). Used Backward Chaining.
  - XCON / R1: Computer hardware configuration at DEC (1980s). Commercially highly successful.

  Limitations of Expert Systems:
  - Fragile: Cannot handle situations outside their domain knowledge.
  - Hard to maintain: Adding new rules can conflict with existing ones.
  - Cannot handle uncertainty well.
  - Cannot learn from new data automatically.

Search Strategy Selection Guide:
  Use BFS when:    Solution at shallow depth, uniform step costs, memory not a concern.
  Use IDS when:    Memory is limited, solution at unknown depth, uniform step costs.
  Use UCS when:    Non-uniform step costs, need optimal cost solution.
  Use A* when:     Have a good admissible heuristic, need optimal guaranteed path.
  Use Greedy when: Speed is more important than optimality, have a good heuristic.
  Use Hill Climb:  Large state space, don't need optimal, accept local optima.
