Introduction to Data Structures & Abstract Data Types (ADT)

A Data Structure is a structured way of ORGANIZING, STORING, and MANIPULATING data in memory
so that operations can be performed efficiently.

Classification of Data Structures:

  Data Structures
       |
       +------> Linear Data Structures
       |           |
       |           +------> Static:   Arrays
       |           +------> Dynamic:  Stacks, Queues, Linked Lists
       |
       +------> Non-Linear Data Structures
                   |
                   +------> Trees:   BST, AVL, Heaps, B-Trees
                   +------> Graphs:  Directed, Undirected

  Classification Matrix:
  +----------------+---------------------------------------------------+----------------------------------+
  | Category       | Description                                       | Examples                         |
  +----------------+---------------------------------------------------+----------------------------------+
  | Linear         | Elements form a sequential sequence. Each has     | Arrays, Stacks, Queues,          |
  |                | unique predecessor & successor (except ends).     | Linked Lists                     |
  | Non-Linear     | Elements arranged hierarchically or in networks.  | Trees, Graphs                    |
  | Static         | Memory size fixed at compile-time.                | Arrays                           |
  | Dynamic        | Memory grows or shrinks at run-time.              | Linked Lists, Stacks, Queues     |
  | Homogeneous    | Stored elements are of the SAME data type.        | Arrays                           |
  | Heterogeneous  | Stored elements can be of DIFFERENT data types.   | Structures in C, Classes         |
  +----------------+---------------------------------------------------+----------------------------------+

Abstract Data Type (ADT):
An ADT is a mathematical model for data types defined by its BEHAVIOR (operations and values)
from the user's perspective, INDEPENDENT of implementation details.

- Interface (WHAT it does): Defines the signature of operations. Example: Push(), Pop() for Stack.
- Implementation (HOW it does it): Actual code using arrays, pointers, or list nodes.

Key Distinction:
  ADT = Interface (contract of operations)
  Data Structure = Concrete implementation of an ADT


Chapter 1: Arrays

An Array is a collection of HOMOGENEOUS elements stored in CONTIGUOUS memory locations.

  Array indices:     [0]     [1]     [2]     [3]     [4]
                  +-------+-------+-------+-------+-------+
  Elements:       |  10   |  20   |  30   |  40   |  50   |
                  +-------+-------+-------+-------+-------+
  Address:          1000    1004    1008    1012    1016     (assuming W = 4 bytes per element)


1.1 One-Dimensional (1D) Array Addressing

Formula to find the physical memory address of element A[i]:
  Address(A[i]) = BA + (i - L) x W

Where:
  BA = Base Address (address of the very first element in memory)
  L  = Lower Bound of index (usually 0 or 1, as declared)
  W  = Width/size of each element in bytes (4 bytes for int, 1 byte for char, 8 bytes for double)

Example:
  Array A[1..5], BA = 1000, W = 4 bytes
  Address(A[3]) = 1000 + (3 - 1) x 4 = 1000 + 8 = 1008


1.2 Two-Dimensional (2D) Array Addressing

For a 2D array A[L1..U1][L2..U2]:
  Number of Rows    R = U1 - L1 + 1
  Number of Columns C = U2 - L2 + 1

Physical memory is 1D, so 2D arrays are MAPPED to 1D using two storage schemes:

--- Row Major Order (RMO) ---
  Elements are stored ROW by ROW. All elements of row 0 first, then row 1, etc.
  Formula for A[i][j]:
    Address(A[i][j]) = BA + ((i - L1) x C + (j - L2)) x W

--- Column Major Order (CMO) ---
  Elements are stored COLUMN by COLUMN. All elements of column 0 first, then column 1, etc.
  Formula for A[i][j]:
    Address(A[i][j]) = BA + ((j - L2) x R + (i - L1)) x W

  Example:
    Array A[1..3][1..4], BA = 2000, W = 2 bytes
    R = 3, C = 4
    RMO: Address(A[2][3]) = 2000 + ((2-1) x 4 + (3-1)) x 2 = 2000 + (4+2) x 2 = 2000 + 12 = 2012
    CMO: Address(A[2][3]) = 2000 + ((3-1) x 3 + (2-1)) x 2 = 2000 + (6+1) x 2 = 2000 + 14 = 2014


1.3 Three-Dimensional (3D) Array Addressing

For a 3D array A[L1..U1][L2..U2][L3..U3]:
  E1 = U1 - L1 + 1  (size of dimension 1)
  E2 = U2 - L2 + 1  (size of dimension 2)
  E3 = U3 - L3 + 1  (size of dimension 3)

--- Row Major Order (RMO) for 3D ---
  Address(A[i][j][k]) = BA + (((i - L1) x E2 + (j - L2)) x E3 + (k - L3)) x W

--- Column Major Order (CMO) for 3D ---
  Address(A[i][j][k]) = BA + (((k - L3) x E2 + (j - L2)) x E1 + (i - L1)) x W

  Memory pattern for RMO 3D: Think of it as "books on a shelf":
  - Pages within a book (innermost: k-dimension)
  - Books (middle: j-dimension)
  - Shelves (outermost: i-dimension)


Chapter 2: Stacks

A Stack is a linear data structure that follows the LAST IN FIRST OUT (LIFO) principle.
ALL insertions and deletions take place at a single end called the TOP.

  Stack (LIFO):
  +------------------+
  |    Element 4     |  <-- top (most recently pushed)
  +------------------+
  |    Element 3     |
  +------------------+
  |    Element 2     |
  +------------------+
  |    Element 1     |  <-- bottom (first pushed, last out)
  +------------------+


2.1 Basic Operations & Boundary Conditions

- Push(element): Inserts an element onto the stack.
  OVERFLOW CHECK (before pushing): if top == MAX - 1, stack is FULL. Cannot push.
  Process: Increment top by 1, then store element at A[top].

- Pop(): Removes and returns the top element.
  UNDERFLOW CHECK (before popping): if top == -1, stack is EMPTY. Cannot pop.
  Process: Fetch A[top], then decrement top by 1.

- Peek() / Top(): Returns the top element WITHOUT removing it.
  UNDERFLOW CHECK: if top == -1, stack is empty.

  State Table:
  +------------------+-------------------+------------------+
  | Stack State      | top value         | Condition        |
  +------------------+-------------------+------------------+
  | Empty Stack      | top == -1         | Underflow guard  |
  | Full Stack       | top == MAX - 1    | Overflow guard   |
  | Normal Stack     | -1 < top < MAX-1  | Push/Pop valid   |
  +------------------+-------------------+------------------+


2.2 Algebraic Expression Formats

- Infix Notation: Operator is between operands. Example: A + B, (A + B) * C
- Prefix Notation (Polish Notation): Operator is BEFORE operands. Example: + A B, * + A B C
- Postfix Notation (Reverse Polish Notation - RPN): Operator is AFTER operands. Example: A B +, A B + C *

  Operator Precedence and Associativity Table:
  +----------------------------------+------------+------------------+
  | Operator                         | Precedence | Associativity    |
  +----------------------------------+------------+------------------+
  | Parentheses ()  [ ]              | Highest    | Left to Right    |
  | Exponentiation ^ or $            | High       | RIGHT to Left    |
  | Multiplication *, Division /     | Medium     | Left to Right    |
  | Addition +, Subtraction -        | Lowest     | Left to Right    |
  +----------------------------------+------------+------------------+

  IMPORTANT: Exponentiation is RIGHT-to-Left associative!
  Example: 2^3^2 = 2^(3^2) = 2^9 = 512, NOT (2^3)^2 = 8^2 = 64.


2.3 Stack Algorithms

--- Algorithm: Infix to Postfix Conversion ---
  1. Initialize an empty STACK and an empty OUTPUT string.
  2. Scan the Infix expression from LEFT to RIGHT.
  3. If the token is an OPERAND (variable or number): Append it to OUTPUT.
  4. If the token is an OPEN PARENTHESIS '(': Push it onto the STACK.
  5. If the token is a CLOSE PARENTHESIS ')':
     Pop from STACK and append to OUTPUT until '(' is encountered.
     Pop and DISCARD the '(' (do not add to output).
  6. If the token is an OPERATOR:
     Pop from STACK and append to OUTPUT all operators with GREATER OR EQUAL PRECEDENCE.
     Then push the current operator onto STACK.
  7. After scanning entire expression: Pop and append ALL remaining operators from STACK to OUTPUT.

  Example: Convert A + B * C - D to Postfix
    Token A: Output = A         Stack = []
    Token +: Output = A         Stack = [+]
    Token B: Output = AB        Stack = [+]
    Token *: Output = AB        Stack = [+, *]  (* has higher precedence than +)
    Token C: Output = ABC       Stack = [+, *]
    Token -: Pop * (+>=-, so pop + too): Output = ABC*+   Stack = [-]
    Token D: Output = ABC*+D    Stack = [-]
    End: Pop -: Output = ABC*+D-
    RESULT: A B C * + D -

--- Algorithm: Postfix Evaluation ---
  1. Scan the Postfix expression from LEFT to RIGHT.
  2. If the token is an OPERAND: Push it onto the STACK.
  3. If the token is an OPERATOR:
     Pop TWO elements: First pop = Right Operand (op2), Second pop = Left Operand (op1).
     Evaluate: Result = op1 [operator] op2
     Push RESULT back onto the STACK.
  4. After scanning entire expression: The SINGLE remaining element in STACK is the final result.

  Example: Evaluate 5 3 2 * + (which is 5 + 3 * 2)
    Token 5: Stack = [5]
    Token 3: Stack = [5, 3]
    Token 2: Stack = [5, 3, 2]
    Token *: Pop 2 and 3 --> 3 * 2 = 6. Stack = [5, 6]
    Token +: Pop 6 and 5 --> 5 + 6 = 11. Stack = [11]
    RESULT = 11 (which equals 5 + 3*2 = 5 + 6 = 11)


2.4 Recursion and the Call Stack

- Recursion is implemented using the system CALL STACK.
- Each recursive call creates an ACTIVATION RECORD (Stack Frame) containing:
  * Function parameters
  * Local variables
  * Return address (where to go back after function completes)

Tower of Hanoi:
  Problem: Move n disks from Peg A to Peg C, using Peg B as auxiliary.
  Rules: Move only one disk at a time. Never place a larger disk on a smaller one.
  Recurrence Relation: T(n) = 2T(n-1) + 1
  Solution: T(n) = 2^n - 1 moves
  Time Complexity: O(2^n) -- exponential!
  Space Complexity: O(n) -- maximum depth of call stack.


Chapter 3: Queues

A Queue is a linear data structure that follows FIRST IN FIRST OUT (FIFO) principle.
Insertions are done at the REAR end. Deletions are done at the FRONT end.

  Queue (FIFO):
  +---+---+---+---+---+
  | 1 | 2 | 3 | 4 | 5 |  <-- Inserted from right (rear)
  +---+---+---+---+---+
  ^                   ^
  front               rear
  (Dequeue here)      (Enqueue here)


3.1 Linear Queue Implementation Using Arrays

Initial state: front = -1, rear = -1

Enqueue(element):
  - If rear == MAX - 1: OVERFLOW (queue full).
  - If queue is EMPTY (front == -1): Set front = 0, rear = 0. Store element.
  - Else: Increment rear by 1. Store element at A[rear].

Dequeue():
  - If front == -1: UNDERFLOW (queue empty).
  - Fetch element = A[front].
  - If it was the LAST element (front == rear): Reset front = -1, rear = -1.
  - Else: Increment front by 1.

  DRAWBACK of Linear Queue:
  If elements are dequeued, the empty slots at the FRONT cannot be REUSED because rear
  remains at MAX-1. This causes FALSE OVERFLOW errors!
  Solution: Use CIRCULAR QUEUE.


3.2 Circular Queue

To reuse freed spaces, CONNECT the last position back to the first position.

  Circular Queue visualized (MAX = 8):
         [0]
        /   \
      [7]   [1]
      /         \
    [6]         [2]
      \         /
      [5]   [3]
        \   /
         [4]

All operations use MODULAR ARITHMETIC: index = (index + 1) % MAX

Boundary Conditions:
  Overflow: (rear + 1) % MAX == front  (queue is FULL)
  Underflow: front == -1               (queue is EMPTY)

Enqueue(element):
  1. Check Overflow: if (rear + 1) % MAX == front --> ERROR.
  2. If Empty: front = 0, rear = 0.
  3. Else: rear = (rear + 1) % MAX.
  4. Store: A[rear] = element.

Dequeue():
  1. Check Underflow: if front == -1 --> ERROR.
  2. Fetch: element = A[front].
  3. If single element (front == rear): Reset front = -1, rear = -1.
  4. Else: front = (front + 1) % MAX.


3.3 Double-Ended Queue (Deque)

A Deque (pronounced 'deck') allows insertions AND deletions at BOTH ENDS (Front and Rear).

Types:
- Input-Restricted Deque: Insertions at ONLY ONE end (Rear). Deletions at BOTH ends.
- Output-Restricted Deque: Deletions at ONLY ONE end (Front). Insertions at BOTH ends.


3.4 Priority Queue

A queue where each element has a PRIORITY associated with it.
- Elements are inserted in any order.
- Deletion/processing order is based on PRIORITY (highest priority first).
- Elements with EQUAL priority are processed in FIFO order.

Implementation Comparison:
  +--------------------+--------------------+--------------------+
  | Implementation     | Enqueue (Insert)   | Dequeue (Remove)   |
  +--------------------+--------------------+--------------------+
  | Unordered Array    | O(1) -- just append| O(n) -- scan all   |
  | Ordered Array      | O(n) -- find pos.  | O(1) -- take first |
  | Binary Heap        | O(log n) -- optimal| O(log n) -- optimal|
  +--------------------+--------------------+--------------------+

  Binary Heap is the PREFERRED implementation for Priority Queues in practice.


Chapter 4: Linked Lists

A Linked List is a DYNAMIC, NON-CONTIGUOUS linear data structure where elements (nodes) are
allocated dynamically in memory and linked using POINTERS.

  Singly Linked List (SLL):
  [Head] --> [Data | *next] --> [Data | *next] --> [Data | NULL]
               Node 1              Node 2              Node 3 (tail)


4.1 Array vs. Linked List Comparison Matrix

  +----------------------+--------------------------------+----------------------------------+
  | Criteria             | Array                          | Linked List                      |
  +----------------------+--------------------------------+----------------------------------+
  | Size                 | STATIC (fixed at compile-time) | DYNAMIC (allocated at run-time)  |
  | Memory Allocation    | CONTIGUOUS (sequential blocks) | NON-CONTIGUOUS (scattered)       |
  | Access Time          | O(1) - Random access via index | O(n) - Sequential traversal      |
  | Insertion/Deletion   | O(n) - Requires shifting elems | O(1) - Only pointer manipulation |
  | Memory Overhead      | NONE (no extra pointers)       | HIGH (extra bytes for pointers)  |
  | Cache Performance    | EXCELLENT (spatial locality)   | POOR (non-contiguous in memory)  |
  +----------------------+--------------------------------+----------------------------------+

  When to use ARRAY: Frequent random access, known size, cache performance critical.
  When to use LINKED LIST: Frequent insertions/deletions, unknown or dynamic size.


4.2 Types of Linked Lists

--- Singly Linked List (SLL) ---
  Each node contains:
    - data: The actual stored value.
    - next: Pointer to the SUCCESSOR node (next node in sequence).
  Last node's next pointer = NULL.

  Diagram: [Head] --> [10|*] --> [20|*] --> [30|NULL]

  Operations:
  - Insertion at Head: O(1) -- create node, point to current head, update head.
  - Insertion at Tail: O(n) -- traverse to last node, update its next pointer.
  - Deletion of given node: O(n) -- find node's PREDECESSOR (no backward pointer), update.
  - Search: O(n) -- sequential scan.

--- Doubly Linked List (DLL) ---
  Each node contains THREE fields: prev pointer, data, next pointer.
  - Allows BIDIRECTIONAL TRAVERSAL.
  - Deletion of a given node is O(1) if node pointer is given (predecessor is readily available).

  Diagram: [Head] --> [NULL|10|*] <--> [*|20|*] <--> [*|30|NULL]

  Advantages over SLL:
  - Can traverse in BOTH directions.
  - Deletion is O(1) with direct node access (no need to find predecessor).
  - Can easily implement LRU Cache, browser back/forward navigation.

--- Circular Linked List (CLL) ---
  The last node's next pointer points back to the FIRST node (Head).
  - NO node points to NULL.
  - Can traverse the ENTIRE list starting from any node.
  - Useful for: Round-robin scheduling, circular buffers.

  Diagram: [Head] --> [10|*] --> [20|*] --> [30|*] --> (back to [10|*])


Chapter 5: Trees

A Tree is a NON-LINEAR, HIERARCHICAL data structure consisting of nodes connected by directed edges.
Each node has exactly ONE parent (except the root, which has no parent).

  Binary Tree Example:
               [A]  (Root Node -- Level 0)
              /   \
           [B]    [C]              (Level 1)
          /   \      \
        [D]   [E]   [F]  (Leaf)   (Level 2)


5.1 Basic Terminology

- Root: The TOP node of a tree with no parent. Example: A.
- Leaf Node (External Node): A node with ZERO children. Examples: D, E, F.
- Internal Node: A node with at least ONE child. Examples: A, B, C.
- Degree of a Node: Total NUMBER OF CHILDREN of that node.
- Height of a Node: Number of edges on the LONGEST PATH from that node to a LEAF.
- Depth of a Node: Number of edges from the ROOT to that node.
- Height of a Tree: Height of the ROOT node (longest path from root to any leaf).

  Formula for Perfect Binary Tree:
  - Total nodes at level i: 2^i
  - Total nodes in tree of height h: N = 2^(h+1) - 1 (if root is at height h and level 0)
  - Height of perfect binary tree with N nodes: h = log2(N+1) - 1


5.2 Binary Trees

A tree where every node can have AT MOST 2 children (Left Child and Right Child).

Special Binary Tree Classifications:
1. Full (Strict) Binary Tree: Every node has EITHER 0 OR 2 children. NO node has exactly 1 child.
   Property: If there are L leaf nodes, there are L-1 internal nodes. Total nodes = 2L - 1.

2. Complete Binary Tree: All levels are COMPLETELY FILLED except possibly the LAST level,
   which must be filled from LEFT TO RIGHT.
   Used in: Binary Heaps (stored efficiently in arrays).

3. Perfect Binary Tree: ALL internal nodes have EXACTLY 2 children, and ALL leaves are at the SAME LEVEL.
   Total nodes = 2^(h+1) - 1, where h is the height of the tree.

4. Balanced Binary Tree: Height difference between left and right subtree of EVERY NODE is at most 1.
   Examples: AVL Trees, Red-Black Trees.

Memory Representations:
- Array (Sequential) Representation: Ideal for Complete/Perfect Binary Trees.
  For a node at index i (0-indexed):
    Left Child index   = 2*i + 1
    Right Child index  = 2*i + 2
    Parent index       = floor((i - 1) / 2)

- Linked Representation: Each node contains data + left child pointer + right child pointer.
  More flexible. Used for all types of binary trees.


5.3 Tree Traversals

Standard methods for VISITING ALL NODES in a binary tree. Each visits every node EXACTLY ONCE.

  Tree Structure:
       [Root]
       /    \
  [Left]    [Right]

1. Preorder Traversal (Root --> Left --> Right):
   Visit Root FIRST, then traverse LEFT subtree, then traverse RIGHT subtree.
   Example on [A, B, D, E, C, F]: A B D E C F

2. Inorder Traversal (Left --> Root --> Right):
   Traverse LEFT subtree, Visit Root, traverse RIGHT subtree.
   IMPORTANT: Inorder traversal of a BST gives SORTED ORDER!
   Example: D B E A C F

3. Postorder Traversal (Left --> Right --> Root):
   Traverse LEFT, traverse RIGHT, Visit Root LAST.
   Used in: Expression tree evaluation, freeing tree memory.
   Example: D E B F C A

4. Level Order Traversal (BFS):
   Visit nodes LEVEL by LEVEL from top to bottom, left to right.
   Implementation: Uses a QUEUE.
   Example: A B C D E F


5.4 Binary Search Tree (BST)

A Binary Tree possessing the BST ORDERING PROPERTY:
- All values in the LEFT SUBTREE < parent node value.
- All values in the RIGHT SUBTREE > parent node value.
- This property holds RECURSIVELY for every node.

CRUCIAL PROPERTY: Inorder Traversal of a BST ALWAYS outputs values in SORTED ASCENDING ORDER.

Operations & Complexity:
- Search / Insert: O(h) where h = height of tree.
  * Balanced BST: O(log n)  -- ideal case
  * Skewed BST (worst case): O(n)  -- when all nodes form a chain

Deletion Cases:
1. Case 1 - Node is a LEAF: Simply REMOVE the node (no children to worry about).

2. Case 2 - Node has ONE CHILD: BYPASS the node by linking its parent directly to its child.
   Parent --> deleted node --> Child  becomes  Parent --> Child

3. Case 3 - Node has TWO CHILDREN: Replace node's value with INORDER SUCCESSOR or INORDER PREDECESSOR.
   - Inorder Successor: SMALLEST value in the RIGHT subtree.
   - Inorder Predecessor: LARGEST value in the LEFT subtree.
   Then RECURSIVELY delete that successor/predecessor node (which has at most 1 child).

  BST Example:
        50
       /  \
      30   70
     / \   / \
    20 40 60  80

  Inorder: 20 30 40 50 60 70 80 (sorted!)
  Delete 50 (two children): Replace with Inorder Successor = 60. Delete 60 from right subtree.


5.5 Threaded Binary Tree

In a normal binary tree of N nodes, there are N+1 NULL POINTERS (wasted!).

A Threaded Binary Tree utilizes these null pointers to store THREADS (pointers to in-order neighbors):
- Left null pointer --> points to INORDER PREDECESSOR.
- Right null pointer --> points to INORDER SUCCESSOR.

Advantage: Allows STACK-LESS and RECURSION-LESS traversal of the tree.
This makes traversal faster (no function call overhead) and uses less memory.


5.6 Huffman Coding

A GREEDY, VARIABLE-LENGTH PREFIX coding algorithm used for LOSSLESS data compression.

Properties:
- Frequently occurring characters get SHORTER codes.
- Less frequent characters get LONGER codes.
- All codes are PREFIX-FREE (no code is a prefix of another code).

Algorithm to Build Huffman Tree:
1. Count the FREQUENCIES of all characters in the source text.
2. Place all characters as LEAF NODES in a min-priority queue sorted by frequency.
3. Repeatedly:
   a. Extract the TWO LOWEST FREQUENCY nodes from the queue.
   b. Create a new internal node with frequency = sum of the two nodes.
   c. Insert the new node back into the priority queue.
4. The remaining SINGLE NODE in the queue is the ROOT of the Huffman Tree.
5. Assign '0' to LEFT edges, '1' to RIGHT edges.
6. Read codes by tracing path from ROOT to each LEAF.

Example:
  Characters: a(45), b(13), c(12), d(16), e(9), f(5)
  Most frequent 'a' gets shortest code: 0
  Least frequent 'f' gets longest code: 1100

Compression ratio: Huffman gives optimal prefix-free codes.


5.7 Self-Balancing Trees

--- AVL Trees (Adelson-Velsky and Landis, 1962) ---
  A self-balancing Binary Search Tree where the BALANCE FACTOR (BF) of every node is restricted to {-1, 0, 1}.

  BF(node) = Height(Left Subtree) - Height(Right Subtree)
  Valid values: -1 (right-heavy), 0 (balanced), +1 (left-heavy)

  If BF deviates outside {-1, 0, 1} after insertion/deletion, one of FOUR ROTATIONS is performed:

  Single Rotations:
    - LL Rotation (Right Rotation): Applied when BF > 1 and left child is also left-heavy.
    - RR Rotation (Left Rotation):  Applied when BF < -1 and right child is also right-heavy.

  Double Rotations:
    - LR Rotation (Left then Right): Applied when BF > 1 and left child is right-heavy.
    - RL Rotation (Right then Left): Applied when BF < -1 and right child is left-heavy.

  Guaranteed O(log n) for search, insert, and delete.

--- B-Trees ---
  A SELF-BALANCING, MULTIWAY search tree designed for DISK/FILE SYSTEMS.
  Can store multiple keys per node, reducing disk I/O operations.

  A B-tree of ORDER m satisfies:
  1. Every node has AT MOST m children.
  2. Every INTERNAL NODE (except root) has at least ceil(m/2) children.
  3. Root has at least 2 children if it is NOT a leaf.
  4. ALL LEAF NODES are at the SAME LEVEL.
  5. An internal node with k children contains EXACTLY k-1 keys.

  Difference from BST: Multiple keys per node. Designed for block-based storage (hard drives, SSDs).

--- Binary Heaps ---
  A COMPLETE BINARY TREE that satisfies the HEAP PROPERTY.

  Max-Heap: Value of each node >= values of its children. ROOT is the MAXIMUM element.
  Min-Heap: Value of each node <= values of its children. ROOT is the MINIMUM element.

  Storage: Heaps are stored EFFICIENTLY as ARRAYS (complete binary tree property allows this).
    For node at index i (0-indexed):
      Left child: 2*i + 1
      Right child: 2*i + 2
      Parent: floor((i-1)/2)

  Complexity:
  +----------------------+---------------+----------------------------------------------+
  | Operation            | Complexity    | Method                                       |
  +----------------------+---------------+----------------------------------------------+
  | Insertion            | O(log n)      | Insert at end, then UP-HEAPIFY (bubble up)   |
  | Delete Min/Max       | O(log n)      | Remove root, put last elem at root, DOWN-HEAPIFY |
  | Build Heap (n items) | O(n)          | Floyd's Algorithm (bottom-up heapification)  |
  | Search               | O(n)          | No ordering property for non-root elements   |
  +----------------------+---------------+----------------------------------------------+

  Heap Sort: Build Max-Heap in O(n), then repeatedly extract max: O(n log n) total.


Chapter 6: Graphs

A Graph is a non-linear data structure defined as G = (V, E), consisting of:
  V = Set of VERTICES (nodes)
  E = Set of EDGES (connections between vertices)

  Types:
  - Directed Graph (Digraph): Edges have direction. Edge (u, v) ≠ Edge (v, u).
  - Undirected Graph: Edges have NO direction. Edge {u, v} = Edge {v, u}.
  - Weighted Graph: Each edge has a numerical WEIGHT (cost, distance).
  - Unweighted Graph: All edges have equal weight.


6.1 Graph Representations

--- Adjacency Matrix ---
  A 2D array of size V x V where A[i][j] = 1 if there is an edge from vertex i to vertex j, else 0.
  For weighted graphs: A[i][j] = edge weight (or infinity if no edge).

  Properties:
  - Space Complexity: O(V^2) -- regardless of number of edges.
  - Edge lookup (is there an edge vi --> vj?): O(1) -- direct array access.
  - Finding all neighbors of a vertex: O(V) -- scan entire row.
  - BEST FOR: DENSE GRAPHS where E is close to V^2.

--- Adjacency List ---
  An array of size V where each index i points to a LINKED LIST of all neighbors of vertex i.
  For weighted graphs: Store (neighbor, weight) pairs in the list.

  Properties:
  - Space Complexity: O(V + E) for directed graphs, O(V + 2E) for undirected graphs.
  - Edge lookup: O(degree(v)) -- scan neighbor list.
  - Finding all neighbors: O(degree(v)) -- much better for sparse graphs.
  - BEST FOR: SPARSE GRAPHS where E << V^2.

  Comparison:
  +------------------+-----------------+-----------------+
  | Feature          | Adjacency Matrix | Adjacency List  |
  +------------------+-----------------+-----------------+
  | Space            | O(V^2)          | O(V + E)        |
  | Edge lookup      | O(1)            | O(degree(v))    |
  | All neighbors    | O(V)            | O(degree(v))    |
  | Add vertex       | O(V^2)          | O(1)            |
  | Best for         | Dense graphs    | Sparse graphs   |
  +------------------+-----------------+-----------------+


6.2 Graph Traversals

--- Breadth First Search (BFS) ---
  Strategy: Level-by-level EXPLORATION.
  Data Structure: QUEUE (FIFO).

  Algorithm:
  1. Start at source vertex s. Mark s as VISITED. Enqueue s.
  2. While queue is NOT EMPTY:
     a. Dequeue vertex u.
     b. For each UNVISITED neighbor v of u: Mark v as visited. Enqueue v.

  Properties:
  - Time Complexity: O(V + E) -- visits every vertex and edge exactly once.
  - Space Complexity: O(V) for the queue.
  - Applications:
    * Shortest path in UNWEIGHTED graphs (BFS gives shortest path in terms of hops).
    * Finding all reachable vertices from a source.
    * Level-order tree traversal.

--- Depth First Search (DFS) ---
  Strategy: Go as DEEP as possible down each path. BACKTRACK when stuck.
  Data Structure: STACK (LIFO) or RECURSION.

  Algorithm:
  1. Start at source vertex s. Mark s as VISITED.
  2. For each UNVISITED neighbor v of s: Recursively DFS from v.
  3. When all neighbors are visited: BACKTRACK.

  Properties:
  - Time Complexity: O(V + E).
  - Space Complexity: O(V) for the recursion stack.
  - Applications:
    * Cycle detection in graphs.
    * Topological Sort (DAG only): Run DFS, output nodes in REVERSE finishing order.
    * Finding Strongly Connected Components (SCC) -- Kosaraju's or Tarjan's algorithm.
    * Path finding (not necessarily shortest).


Chapter 7: Hashing

Hashing is a technique to MAP keys to specific index positions in a HASH TABLE of size m
to achieve O(1) average case for search, insertion, and deletion.

  Key Terminology:
  - Hash Table: An array of fixed size m.
  - Hash Function h(k): Maps key k to slot in [0, m-1].
  - Collision: When two different keys map to the SAME slot: h(k1) = h(k2) for k1 != k2.
  - Load Factor (alpha) = n / m, where n = number of stored keys.


7.1 Hash Functions

Characteristics of a GOOD hash function:
- Computationally FAST (O(1) to compute).
- Distributes keys UNIFORMLY across slots (minimizes collisions).
- Deterministic (same key always maps to same slot).

Common Hash Functions:
1. Division Method: h(k) = k mod m
   Best practice: m should be a PRIME NUMBER not close to a power of 2.

2. Mid-Square Method:
   Square the key: k^2. Extract r middle digits as the index.
   Example: k = 3121, k^2 = 9,740,641. Middle digits: 406. h(k) = 406.

3. Folding Method:
   Divide key into EQUAL parts. Add the parts. Take modulo m.
   Example: k = 123456789, m = 1000. Parts: 123, 456, 789. Sum = 1368. h(k) = 368.


7.2 Collision Resolution Techniques

A collision occurs when h(k1) = h(k2) for k1 != k2.

  Collision Resolution Methods:
    Collision Resolution
          |
          +-------> Open Addressing (Closed Hashing)
          |                 |
          |                 +--> Linear Probing
          |                 +--> Quadratic Probing
          |                 +--> Double Hashing
          |
          +-------> Closed Addressing (Open Hashing / Chaining)

--- Open Addressing (Closed Hashing) ---
  ALL elements are stored WITHIN the hash table itself.
  If a slot is occupied, search for another EMPTY SLOT using a probe sequence.

  1. Linear Probing:
     h(k, i) = (h'(k) + i) mod m, where i = 0, 1, 2, ...
     Search slots SEQUENTIALLY (0, 1, 2, ...) until empty slot found.

     DRAWBACK: PRIMARY CLUSTERING -- Long runs of occupied slots build up.
     This slows down insertions and lookups dramatically as table fills up.

  2. Quadratic Probing:
     h(k, i) = (h'(k) + c1*i + c2*i^2) mod m
     Search slots using a QUADRATIC OFFSET (0, c2, 4c2, 9c2, ...).

     DRAWBACK: SECONDARY CLUSTERING -- Keys with same initial hash follow SAME probe sequence.

  3. Double Hashing:
     h(k, i) = (h1(k) + i * h2(k)) mod m
     Use a SECOND HASH FUNCTION h2(k) to compute the probe step size.

     ADVANTAGE: ELIMINATES both primary and secondary clustering.
     Each key gets a UNIQUE probe sequence (with high probability).
     BEST OPEN ADDRESSING TECHNIQUE in practice.

--- Closed Addressing (Chaining) ---
  Each SLOT in the hash table points to a LINKED LIST of entries that hash to the same index.
  Multiple elements can coexist at the same slot.

  Advantages:
  - Simple to implement.
  - Table NEVER FILLS UP (load factor alpha can exceed 1).
  - Performance degrades GRACEFULLY as alpha increases.

  Disadvantages:
  - Extra memory overhead for POINTERS in linked list nodes.
  - Poor cache performance (non-contiguous memory access).

  Performance Analysis:
  - Search (Successful): O(1 + alpha/2) average case.
  - Search (Unsuccessful): O(1 + alpha) average case.
  - For low load factor (alpha < 0.7): Near O(1) performance.

  Open Addressing vs. Chaining Comparison:
  +----------------------+---------------------------+----------------------------+
  | Feature              | Open Addressing           | Chaining                   |
  +----------------------+---------------------------+----------------------------+
  | Storage              | Only within table         | External (linked lists)    |
  | Max Load Factor      | < 1 (table can fill up)   | > 1 (no limit)             |
  | Cache Performance    | Better (sequential)        | Worse (pointer chasing)    |
  | Deletion             | Tricky (lazy deletion)    | Easy (remove from list)    |
  | Best for             | Small, fixed sets         | Dynamic, unknown sizes     |
  +----------------------+---------------------------+----------------------------+


Quick Revision: High-Yield Summary

Array Addressing Formulas:
  1D: Address(A[i]) = BA + (i - L) x W
  2D RMO: Address(A[i][j]) = BA + ((i - L1) x C + (j - L2)) x W
  2D CMO: Address(A[i][j]) = BA + ((j - L2) x R + (i - L1)) x W

Stack Boundary Conditions:
  Empty: top == -1      (Underflow condition)
  Full: top == MAX-1    (Overflow condition)
  Operations: LIFO -- Last pushed is first popped.

Queue Boundary Conditions:
  Linear: Overflow when rear == MAX-1. False overflow problem.
  Circular: Overflow when (rear+1)%MAX == front. Solves false overflow.

BST Properties:
  Inorder Traversal: Always gives SORTED order.
  Best case height: O(log n) -- balanced tree.
  Worst case height: O(n) -- skewed tree (all inserts in sorted order).

Heap Properties:
  Max-Heap: Every parent >= its children. Root = maximum.
  Min-Heap: Every parent <= its children. Root = minimum.
  Build Heap: O(n) using Floyd's bottom-up algorithm.

Hash Table Collision Strategies:
  Best Open Addressing: Double Hashing (no clustering).
  Best Closed Addressing: Chaining (flexible, no overflow).

AVL Tree: BF of every node must be in {-1, 0, 1}.
B-Tree: All leaf nodes at same level. Order m: max m children per node.
Huffman: Greedy. Most frequent character gets shortest prefix code.
